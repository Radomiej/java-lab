# Lab Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Prefer execution in this chat without parallel agents unless the user chooses otherwise.

**Goal:** Pokazać aktywne sesje Java Lab i kod uczniów na żywo bez uzależniania nauki od sieci.

**Architecture:** Endpointy Java Lab na Vercel publikują persistent JSON przez HTTPS API istniejącego RabbitMQ. Osobny C:/Nauka/lab-admin odbiera AMQP, zapisuje SQLite i udostępnia chroniony panel React przez SSE. Lokalny test obu projektów poprzedza wdrożenie.

**Tech Stack:** Node.js 24, React 18, Vite, Vitest, node:test, node:sqlite, amqplib, natywne fetch i SSE.

**Spec:** C:/Nauka/java-lab/docs/superpowers/specs/2026-10-13-lab-admin-design.md

## Global Constraints

- Umami poza zakresem.
- ID instalacji UUID w localStorage; osobny sessionId na kartę.
- Debounce 2 s, maksymalnie 5 s przy ciągłym pisaniu, heartbeat 15 s; aktywność do 45 s od kontaktu.
- Maksymalny JSON 256 KiB; konsola maksymalnie 20 000 znaków.
- Kolejka java-lab.activity, vhost /, exchange domyślny; istniejące ustawienia durable classic i 50 MiB zachowane.
- Retencja 7 dni; limit historii 500 MiB; bounded quarantine.
- Brak połączenia nigdy nie blokuje edycji, zapisu postępu, kompilacji ani sprawdzania. Timeout 8 s; bufor 20 zdarzeń; backoff 2–30 s.
- Sekrety wyłącznie po stronie serwera. Panel wymaga logowania; kod renderowany jako tekst.
- Nie nadpisywać ani nie commitować zastanych zmian użytkownika. Nie publikować produkcyjnie bez testu przepływu.

## Review Focus

1. Niedostępna sieć i storage: nauka działa, pamięć nie rośnie bez limitu (zadanie 2).
2. Równoległe karty i spóźnione wiadomości: brak nadpisywania sesji i cofania snapshotu (zadania 2 i 3).
3. Restart pomiędzy zapisem a ACK: brak utraty zapisanego stanu i duplikacji zdarzeń (zadanie 3).
4. Zbyt duży projekt i Unicode: limit w bajtach, czytelny status, brak awarii edytora (zadania 1 i 2).
5. Brak uwierzytelnienia, rozłączenie SSE i treść HTML w kodzie: brak wycieku, pełny resync i brak wykonania kodu (zadania 4 i 5).
